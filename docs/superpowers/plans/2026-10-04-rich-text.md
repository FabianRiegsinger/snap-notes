# Rich Text Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Notes store Markdown plus custom color/highlight/size tags, show it rendered when open, switch to the existing raw editor on click, and support links and images stored in `images/`.

**Architecture:** A pure `rich` module parses note content (pulldown-cmark plus a tag scanner) into blocks of styled spans and offers text helpers (plain text, task toggle, selection wrapping). A pure `images` module imports, resolves and sweeps image files. `note_panel` renders the parsed blocks with iced `rich_text`/`image` or shows the existing `text_editor` with a toolbar, and `app` owns the edit/render mode and the new messages.

**Tech Stack:** Rust 2021, iced 0.14 (`image` feature added), pulldown-cmark, arboard, rfd, tempfile (tests).

**Spec:** `docs/superpowers/specs/2026-10-04-rich-text-design.md`

## Global Constraints

- `Note.content` stays a `String`; no change to `note.rs` serialization, no migration.
- Tag color names, in slot order: `coral, rose, blush, peach, tangerine, amber, lemon, sand, lime, sage, mint, teal, aqua, sky, cornflower, periwinkle, lavender, orchid, mocha, slate`, matched case-insensitively, resolved against the **current** palette slot.
- `==text==` equals `{bg:amber}text{/}`. Size is clamped to 8–48.
- Headings: H1 22 px, H2 18 px, H3 16 px (H4–H6 render as H3); body 14 px; list indent 16 px per depth.
- Toolbar sizes: small 12, normal 14, large 20, huge 28.
- Images: `png, jpg, jpeg, gif, webp` (case-insensitive), at most 20 MB, stored as `images/<uuid>.<ext>` beside `notes.json`.
- Links open only for `http`, `https`, `mailto`.
- The parser must never panic on any input.
- Crate versions named in this plan are starting points: use the newest release compatible with iced 0.14 and the current toolchain, and note any change in the commit message.
- CI runs `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --bin snap-notes`; every task leaves all three green.
- Comments and naming follow the surrounding code: short doc comments on public items, no section banners.

## Review Focus

1. **Multi-byte text in the editor:** `text_editor::Position.column` vs byte offsets when wrapping a selection that contains `é` or emoji. Expect no panic and correct wrapping. Test in Task 5 (`wrap_selection_with_multibyte_text`).
2. **CRLF content:** a hand-edited `notes.json` with `\r\n` line endings. Expect `source_line` and `toggle_task` to still address the right line. Test in Task 2 (`toggle_task_preserves_crlf`).
3. **Image text the user typed by hand,** like `![](../notes.json)` or `![](images/sub/x.png)`. Expect a placeholder, never a file read outside `images/`. Test in Task 3 (`resolve_rejects_escapes`).
4. **Sweep with no `images/` dir,** or with a file the user placed there. Expect `Ok(0)` and the user's file untouched. Tests in Task 3 (`sweep_without_dir_is_ok`, `sweep_keeps_foreign_files`).
5. **Old plain notes** that start lines with `#`, `-` or `1.`, or contain `{` or `}`, such as code snippets or JSON. Expect lists and headings to render as Markdown, braces that aren't tags to stay literal, and no lost text. Test in Task 1 (`braces_that_are_not_tags_stay_literal`).

- [ ] **Step 3: Implement `parse`**

Use `pulldown_cmark::Parser::new_ext(content, Options::ENABLE_STRIKETHROUGH | Options::ENABLE_TASKLISTS).into_offset_iter()`. Compute `source_line` as the count of `\n` in `content[..range.start]` at each block's `Start` event. Keep an emphasis/link stack from Markdown events. Lists: track nesting depth with a counter on `Start(List)`/`End(List)`; read a task marker from `TaskListMarker(bool)`.
