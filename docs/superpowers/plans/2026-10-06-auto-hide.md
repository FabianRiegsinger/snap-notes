# Auto-hide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to carry out this plan task by task.

**Goal:** implement the spec `docs/superpowers/specs/2026-10-06-auto-hide-design.md`, decisions A1–A14.

**Architecture:** a pure state machine (`src/autohide.rs`). The app feeds it inputs on each tick and cursor event and applies the x-offset it returns to the strip and its overlays. On macOS and Windows the hidden strip uses the existing passthrough. On Linux the window shrinks to a 2 px sliver.

**Tech stack:** Rust 2021, iced 0.14. Tests run with `cargo test --bin snap-notes`. Checks are `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, and the Linux and Windows cross-checks (`cargo check --all-targets --target x86_64-unknown-linux-gnu` and `--target x86_64-pc-windows-msvc`, run with `-D warnings`).

### Task 1: The `autohide` state machine (pure)

**Files:** `src/autohide.rs` (new), `src/main.rs` (the `mod` line).

**Interfaces:**
- `pub enum Phase { Shown, Hiding, Hidden, Revealing }`, deriving `Debug`, `Clone`, `Copy`, `PartialEq` and `Eq`.
- `pub struct Inputs { pub enabled: bool, pub in_edge: bool, pub in_use_area: bool, pub blocked: bool, pub force_reveal: bool }`, deriving `Default`.
- `pub struct AutoHide`, holding the phase, `offset: f32` (0 = shown, 1 = hidden), `edge_since: Option<Instant>` and `idle_since: Option<Instant>`. It has `Default`, which is Shown.
- `pub fn step(&mut self, inputs: Inputs, now: Instant, dt: f32, speed: f32) -> bool`. It returns true while it needs frames or has a pending deadline.
- `pub fn offset(&self) -> f32` returns the eased offset (ease-out cubic for reveals, ease-in cubic for hides; the existing `animation` easing helpers are fine).
- `pub fn phase(&self) -> Phase`.
- `pub fn is_hidden(&self) -> bool`.
- `pub fn next_deadline(&self) -> Option<Instant>`: the dwell or grace deadline still pending, so the app can schedule a wake-up.
- Constants: `REVEAL_DWELL = 150 ms`, `HIDE_GRACE = 800 ms`, `SLIDE_SECS = 0.2`. The slide length is divided by `speed`, and `speed` comes from the motion setting.

**Rules:**
- `!enabled` reveals at once: the phase becomes Shown and the offset jumps to 0, with no slide.
- `force_reveal` or `blocked`: from Hidden or Hiding, switch to Revealing. The reveal reverses from the current offset.
- `in_use_area` resets `idle_since`, and so does `blocked`.
- When Shown, not blocked and `!in_use_area` for `HIDE_GRACE`, switch to Hiding.
- When Hidden and `in_edge` continuously for `REVEAL_DWELL`, switch to Revealing. Leaving the edge resets `edge_since`.
- The offset moves by `dt / (SLIDE_SECS / speed)` per step. Revealing ends in Shown at 0, and Hiding ends in Hidden at 1.

**Tests:**
- `disabled_is_always_shown`
- `hides_after_grace_when_idle` (799 ms: still Shown; 800 ms: Hiding)
- `reentry_resets_grace`
- `dwell_reveals_after_150ms` (149 ms: no reveal)
- `leaving_edge_resets_dwell`
- `blocked_prevents_and_reverses_hide`
- `force_reveal_skips_dwell`
- `slide_offset_is_monotonic_and_reaches_bounds`
- `mid_slide_reversal_continues_from_current_offset`
- `disabling_reveals_instantly`
- `next_deadline_reports_pending_timer`

**Commit:** `feat: auto-hide state machine`

### Task 2: The setting and app wiring (macOS and Windows behaviour, and the shared logic)

**Files:** `src/app.rs`, `src/bar_strip.rs`, `src/settings_panel.rs`, `src/settings.rs` (only if the toggle type lives there; the flag itself is session-only).

**Steps:**
1. **Setting.**
   - Add the session-only `App.auto_hide_on: bool`, false at start and never saved (A1, A12).
   - Add the Window-group toggle labelled exactly `"Auto-hide"`. It sends `Message::AutoHideToggled(bool)`.
   - Read how `SettingToggle` and the Window group render. The toggle must not go through the persisted settings JSON. Pass the bool to the panel view as an argument, and add an explicit message for it.
2. **State.** Add `App.auto_hide: AutoHide`.
3. **Inputs** (`fn auto_hide_inputs(&self) -> Inputs`):
   - `enabled = auto_hide_on && visible`.
   - `in_edge`: the last cursor is within the rightmost 2 px of the window and within the strip band. Factor out a pure `strip_band(&StripLayout, gap) -> (f32, f32)`, the same band `is_interactive` uses today.
   - `in_use_area`: the cursor is over the strip column within the band, over the peek rect, or over the toast rect.
   - `blocked` (A7): search, settings or export open; a drag in progress; a file hovering; the undo toast or clipboard hint showing; any note pulsing; `export_dialog_open`. An open note does **not** count (A14).
   - `force_reveal` is a one-shot flag the app sets for A8 and A9 and consumes on the next step.
4. **Driving.**
   - Step the machine on every Tick, on cursor moves and cursor polls, and on any message that changes the blockers.
   - Use `animating` while it returns true.
   - Schedule a wake-up at `next_deadline()` with the existing `delayed` helper or a timer subscription, so the dwell and grace fire without mouse motion.
   - Polling while hidden: cursor polling already runs while `passthrough` is on. Make sure it keeps running while Hidden.
5. **Rendering.** Add `BarStrip.x_offset: f32`, set to `auto_hide.offset() * (STRIP_WIDTH + margin)` where the margin is enough that no shadow or notch stays visible. It is applied to the drawing of the bars, the slots, the peek, the chips and the toast. Hit-testing is off while the offset is above 0.
   - An open note panel is **not** offset (A14).
   - A note folding closed targets its bar's rect, which is offset, so the morph target must include the offset. Read the morph target rect code.
6. **Interactivity.** In `is_interactive`, while the offset is above 0, only the edge zone and open note or panel frames count. The strip, peek and toast do not count until they are fully shown.
7. **Reveal hooks.** These set `force_reveal`:
   - the reminder fire path (A8): wherever `pulsing` gains an id;
   - `HotkeyPressed`, the tray New Note, New Note from Clipboard, Search… and Settings… items, Cmd/Ctrl+N, Cmd/Ctrl+F, `ToggleSearch`, and `AddNote`, all for A9;
   - tray Show and Hide keep their current meaning (A10). Because `enabled` requires `visible`, Show returns to the auto-hide behaviour.
8. **Turning it off** reveals at once (A1).

**Tests:**
- `auto_hide_off_at_start_and_not_saved`
- `idle_strip_hides_and_only_edge_is_interactive`
- `edge_dwell_reveals_strip`
- `open_note_does_not_block_hiding_and_stays_interactive`
- `panel_open_blocks_hiding`
- `reminder_fire_reveals_and_pulse_keeps_shown`
- `hotkey_reveals_strip`
- `tray_hide_overrides_auto_hide`
- `turning_auto_hide_off_reveals`
- `strip_ignores_clicks_while_offset` (bar_strip)

Drive time with explicit Instants, the way the existing tests use `Tick(now)`.

**Commit:** `feat: auto-hide the strip until the screen edge is touched`

### Task 3: Linux (no passthrough) sliver window

**Files:** `src/app.rs`.

**Steps:**
1. Extend `needs_wide_window` and `docked_width` (or add a pure helper `fn docked_width_for(passthrough, wide, hidden) -> f32`): when there is no passthrough, the strip is Hidden and no note or panel is open, the width is `EDGE_SLIVER = 2.0`.
2. `dock_window` re-runs when the phase changes to Hidden (shrink) or to Revealing (widen first, then slide).
3. Without passthrough there is no polling, so `CursorEntered` and `CursorMoved` inside the sliver set `in_edge`, and `CursorLeft` clears it. Read the window events subscription. With a note open, the wide window uses the rightmost 2 px within the band, as in Task 2.

**Tests:**

- `sliver_grows_before_reveal_slide`
- `sliver_not_used_while_note_open`
